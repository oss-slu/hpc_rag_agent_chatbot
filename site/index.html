Answers about SLU's supercomputer, straight from its documentation.

The SLU HPC Assistant is a question-and-answer tool for researchers who use Saint Louis University's high-performance computing cluster. Ask in plain English, and it answers from the official documentation with a link to the page it used.

If the documentation doesn't cover your question, it tells you so instead of making something up.

Powerful, shared, and hard to get started with

A high-performance computing (HPC) cluster is a large group of powerful computers that the whole university shares. Biologists use it to analyze DNA, physicists to run simulations, social scientists to process large datasets. Work that would take a laptop months can finish in hours.

Using it is not like using a laptop. You write a short job script that says what to run and how much computing power you need, then submit it to a scheduler that runs it when room opens up. Getting that script right means reading long technical documentation, and many researchers have never worked at a command line.

The answer to most questions is already in the documentation. The hard part is finding the right paragraph. A wrong setting can leave a job waiting for hours or make it fail after it starts, and support staff end up answering the same questions over and over.

myjob.sh
#!/bin/bash
#SBATCH --job-name=protein-fold
#SBATCH --time=04:00:00      # how long it may run
#SBATCH --cpus-per-task=8    # how many processors
#SBATCH --mem=32G            # how much memory

module load python
python fold.py input.fasta
A typical job script. Every line has options and limits specific to SLU's cluster, and the assistant helps people get them right the first time.
Think of it as an open-book exam where the student has to cite the page.

General-purpose AI chatbots answer from what they absorbed during training. They write fluently, but they can state a command or a limit that doesn't exist, and on a shared cluster a wrong detail costs real time.

This assistant uses retrieval-augmented generation, or RAG. Before it answers, it searches SLU's own documentation for the sections that match your question, writes its answer from those sections only, and lists them as sources.

How it works

Part of the work happens ahead of time, so the documentation is ready to search. The rest happens in the seconds after you ask.

Preparing the docs

Runs in the background on a schedule.

  1. 1

    Fetch the official guide

    A scheduled job downloads SLU's HPC documentation. If nothing has changed since last time, it stops here.

  2. 2

    Split it into sections

    The guide is divided at its headings, so each piece covers one topic and remembers where it came from.

    Jobs › GPU partitions
  3. 3

    Index each section

    Each section is stored with an embedding, a numeric summary of its meaning, plus an ordinary word index.

Then someone asks: "Why hasn't my job started?"

Answering

Takes a few seconds.

  1. 4

    Search two ways

    By meaning: "hasn't started" finds the section on pending jobs.
    By exact words: catches specific terms like --gres or a partition name.
  2. 5

    Write the answer

    Claude, an AI model made by Anthropic, reads the matching sections and answers from them. It is told never to guess at limits, file paths or commands.

  3. 6

    Show the sources

    The answer appears as it's written, followed by links to the sections it used. You can mark it helpful or not.

Accuracy and privacy

  • One source of truthAnswers come from SLU's published cluster documentation, not the open internet.
  • Sources on every answerOpen the original page and check any answer yourself.
  • Admits gapsIf the documentation doesn't cover something, it says so and suggests contacting SLU Research Computing.
  • No personal dataQuestions and answers are logged to improve the tool. Usernames and IP addresses are not stored.
  • Tested on real questionsAnswers rated unhelpful go into a test set that every future change is checked against.
  • Kept currentWhen the documentation changes, it is re-indexed, so answers follow the current rules.

Terms on this page

HPC
High-performance computing: many powerful computers working together on problems too big for one machine.
Cluster
The shared group of computers itself.
Node
One computer in the cluster.
Job
One piece of work submitted to the cluster, described in a job script.
Slurm
The scheduler that decides which jobs run where and when. sbatch and squeue are two of its commands.
RAG
Retrieval-augmented generation: an AI looks up trusted documents before it writes an answer.
Embedding
A list of numbers representing what a passage means, so passages about the same idea can be found even when the wording differs.
